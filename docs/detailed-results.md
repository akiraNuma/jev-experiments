### コメント300件の感情ラベル

完全一致は、感情ラベルの組をすべて当てた割合です。
micro F1は全コメントでラベルの過不足を合計して採点します。
両APIとも、しきい値を超えるラベルがなければ最も高いラベルを1つ選びます。

| 方式 | 完全一致 | micro F1 |
| --- | --- | --- |
| Jev、しきい値0.5 | 3.0% | 0.250 |
| Jev、しきい値0.92 | 24.0% | 0.328 |
| Decisions API、しきい値0.5 | 2.0% | 0.222 |
| Decisions API、しきい値0.97 | 21.7% | 0.343 |
| Haiku | 12.3% | 0.322 |
| Sonnet | 16.0% | 0.410 |

Jevの0.92とDecisions APIの0.97は、同じ調整用データ5,426件で、同じ手順（0.01〜0.99を0.01刻み、micro F1が最大）で選びました（`python3 scripts/recipe-report.py`）。
Decisions APIが回答を拒否した感情は、調整（79件）でも比較（5件）でも、付けなかったものとして数えています。正解にある感情なら見逃しで、誤検出にはしません。アプリでは、拒否された感情にラベルが付かないためです。
比較の5件は回答が保存されていないため、ラベルを1つも付けなかったとみなしました（完全一致は不正解）。
完全一致のJev 0.92対Haikuはp<0.0001、対Sonnetはp=0.0043、対Decisions API 0.97はp=0.35です。
micro F1のコメント単位の入れ替え検定は、対Decisions API 0.97がp=0.46、対Haikuがp=0.79、対Sonnetがp<0.0001です（`python3 scripts/report-decisions-book.py`）。

## 実験1：問い合わせを分類する


問い合わせの分類先を、JevとClaudeに1つずつ選ばせました。
学習用のデータを使って作った分類器とも、同じ問い合わせで比べています。
使った公開データは次の2つです。

- Banking77：銀行への英語の問い合わせ。77種類。評価用のデータ（test）3,080件
- MASSIVEの日本語：音声アシスタントへの日本語の発話。60種類。評価用のデータ（test）2,974件。人が英語から訳したもの

### 同じ問い合わせで分類先を比べる

Jevには、分類先の名前だけを並べたChoiceを1問送りました。
ClaudeのHaikuとSonnetにも、問い合わせ文と分類先の一覧を渡しました。
JevにもClaudeにも、分類先の説明や例は付けていません。

表のTF-IDFの分類器は、単語や文字の出現頻度を数値化して使うものです。
この数値から分類先を学ぶ、ロジスティック回帰という方法で作りました。
学習用のデータ（train）は、Banking77が10,003件、MASSIVEが11,514件です。
JevやClaudeに、この学習用のデータは渡していません。

比較には、評価用のデータから400件ずつを等間隔に選びました。
Banking77では、Decisions APIが回答を拒否した2件も不正解として数え、400件で採点しました。

## 実験2：コメントに複数の感情ラベルを付ける


GoEmotionsという、Redditのコメントに感情ラベルを付けた公開データを使いました。
ラベルは「感情なし」を含む28種類で、1件に複数付く場合があります。
Jevには感情ごとのNoulを送り、返った確率から採用する感情を選びました。

しきい値を決める調整用のデータは5,426件（dev区分）です。
採点には、別の評価用のデータ5,427件（test区分）を使っています。

### しきい値を変えて感情ラベルを選ぶ

最初に使ったしきい値では、正解にない感情ラベルまで多く付いていました。
そこで、調整用のデータを使い、感情ごとにしきい値を変える方法と、全感情で共通にする方法を試しました。


<a id="emolabelcount"></a>

最初のしきい値で付いた感情の数

| 対象 | 1コメントあたりの平均 |
| --- | --- |
| Jev、しきい値0.5 | 4.8個 |
| 正解ラベル | 1.2個 |


どの方法でも、しきい値以上の感情がなければ、確率が最も高い感情を1つ採用しました。
次の表は、評価用のデータから等間隔に選んだ300件での結果です。
ClaudeのHaikuとSonnetにも、その300件に感情ラベルを付けさせています。

ラベルごとの過不足はmicro F1、感情の組を丸ごと当てたかは完全一致で示します。
この2つは採点する単位が異なります。


<a id="emoresult"></a>

コメント300件の感情ラベルの判定結果

| 方式 | micro F1 | 完全一致 |
| --- | --- | --- |
| Jev、しきい値0.5 | 0.249 | 2.7% |
| Jev、感情ごとに調整したしきい値 | 0.384 | 13.3% |
| Jev、全感情で共通のしきい値（0.9） | 0.328 | 22.7% |
| Haiku | 0.341 | 12.7% |
| Sonnet | 0.404 | 19.0% |


しきい値の選び方によって、ラベルごとの成績を優先するか、感情の組の一致を優先するかが変わりました。
「感情をなるべく多く拾う」ことと、「余計な感情を付けない」ことを分けて評価する必要があります。

### Claudeと正誤を比べる

同じ評価用のデータ300件で、どちらか一方だけ感情の組を完全に当てた件数を比べました。
しきい値の決め方が違うと、Claudeとの比較結果も変わります。


<a id="emopaired"></a>

| Jevのしきい値と比較相手 | Jevだけ正解 / 相手だけ正解 | p値 |
| --- | --- | --- |
| 感情ごとのしきい値、Haiku | 26 / 24 | 0.89 |
| 感情ごとのしきい値、Sonnet | 16 / 33 | 0.021 |
| 全感情共通のしきい値、Haiku | 46 / 16 | <0.001 |

この違いを、採点指標やしきい値と切り離してモデルの優劣と解釈しないようにします。

### 使うときの注意

「感情なし」の質問も、ほかの感情の答えを参照せずに判定されます。

契約日の抜き出しでのカスケード（98通）

| 方式 | 正解 | Haikuに回した割合 |
| --- | --- | --- |
| Jevだけ | 82.7% | 0% |
| 0.5未満をHaikuへ | 85.7% | 27% |
| 0.9未満をHaikuへ | 87.8% | 92% |
| Haikuだけ | 87.8% | 100% |


Claudeへ回す件数を増やしても、問い合わせ分類のときほど、Jevだけで返す件を残せませんでした。
このデータでは、ほとんどをHaikuへ回す条件で、ようやく全件をHaikuに任せる成績と並びました。
契約日のしきい値は、同じ評価用のデータで比べたものです。
運用する値を決める場合は、別の調整用のデータを使います。

## 実験9：写真を分類する


品種の見本写真を追加すると、説明文だけの場合より写真を分類しやすくなるかを試しました。
モデルの版も変え、同じ評価用のデータで判定しています。

Oxford-IIIT Petから、猫のBritish Shorthair、Russian Blue、Siamese、犬のbeagle、boxer、pugを選びました。
品種ごとに、見本用と動作確認用に1枚ずつ分けました。
評価用のデータには、それらとは別の写真を各品種10枚、計60枚使っています。

実験10でも頭の正解枠を使うため、trainval区分から枠のある写真を選びました。
配布元が指定した評価用のデータとは異なります。
画像IDのハッシュで順番を決め、結果を見て選び直していません。

送信画像は、縦横比を保って384画素四方に収め、白い余白を足しました。
ファイル名、画像ID、正解の品種はstateから省いています。
送信ファイル名にも、品種名やIDを含めていません。

### 同じ写真で分類を比べる

「文章の選択肢」は、品種名の説明だけを送る条件です。
「文章と見本6枚」は、その説明に各品種の見本写真を追加する条件です。


<a id="classification"></a>

同じ60枚の分類結果

| 条件 | 正解 | 1,000枚あたりの費用 |
| --- | --- | --- |
| 1.13、文章の選択肢 | 58/60（96.7%） | $0.0348 |
| 1.14、文章の選択肢 | 58/60（96.7%） | $0.0348 |
| 1.14、文章と見本6枚 | 57/60（95.0%） | $0.1454 |


見本を加えた条件でも、正解は増えませんでした。
誤りはどの条件でも、British ShorthairとRussian Blueの取り違えです。

Jev 1.14では、見本の有無によって結果が変わった写真を確認しました。


<a id="imagepaired"></a>

| 変化 | 写真の枚数 |
| --- | --- |
| 説明文だけで正解し、見本を足すと不正解 | 1枚 |
| 見本を足したときだけ正解 | 0枚 |


McNemar検定のp値は1で、差は偶然と区別できませんでした。
また、58/60の正解率の95%信頼区間は約89〜99%です。
この60枚の結果だけから、未知の写真での精度や、LLM・専用の分類器との優劣は判断できません。

### 見本も含めた費用と待ち時間

前の表の費用には、見本画像を送る分も含めています。
60枚の平均から1,000枚分に換算した金額です。
判定する写真ごとに見本も送り直すため、見本の追加は入力費用にも影響します。
全180リクエストは成功しました。

- 画像入力は実験機能です。指定したモデル名と返ったモデル名を記録し、条件をそろえて比べます

## 実験11：ゲームの次の動作を選ぶ


ViZDoomのdefend_the_centerで、次の動作を選ぶ方法を比べました。
プレイヤーは部屋の中央に立ち、左右を向くか、撃つかを選びます。
敵は四方から近づき、使える弾は26発です。

JevとClaudeのHaikuに渡したのは、敵の横位置と見かけの大きさ、残弾数、体力です。
画面の画像は送っていません。
選ばれた動作は、ViZDoomのボタン入力へ変換して実行しました。

### 動作の選び方と、判定を待つ間の扱い

APIを呼ばずに決める比較相手として、無作為に選ぶ方法と、通常のコードで規則を書く方法を使いました。
規則は、横位置の絶対値が0.1未満の敵がいれば撃つ、というものです。
該当する敵がいなければ最も大きく見える敵のほうへ向き、敵が見えなければ左を向きます。

選んだ動作は4tic分実行しました。
ticはゲームの時間単位で、1秒に35回進み、4ticは約0.11秒です。
その後にゲーム状態を取り直し、次の動作を尋ねています。

ゲームの進め方は、次の2条件に分けました。

- 実時間：判定を待つ間もゲームが進み、プレイヤーは何も操作しない
- 同期：判定を待つ間はゲームを止め、返った動作を実行してから再び尋ねる

Haikuは実時間3回、同期2回で、ほかの方法は測定した条件ごとに10回ずつです。
Jevの最初の版と無作為の方法は、同期の条件では測っていません。
Haikuには、Jevが撃つ範囲を数字で書き直す前の質問を使いました。
質問も試行回数も異なるため、この表でJevとHaikuの優劣は決められません[^doom_haiku_time]。
Haikuは、測定した人の個人設定（`~/.claude/CLAUDE.md`など）を読み込む状態で呼んでいます。本にはHaikuの結果を載せていません。


<a id="doomresult"></a>

倒した敵の数（平均と最小〜最大、Haiku以外は10回）

| 方式 | 実時間 | 同期 |
| --- | --- | --- |
| 無作為 | 1.1（0〜3） | - |
| 規則 | 11.1（8〜15） | 13.9（11〜19） |
| Jev（最初の版） | 1.5（1〜4） | - |
| Jev（数字で書いた版） | 3.0（1〜5） | 13.1（11〜16） |
| Haiku | 2.0（1〜3、3回） | 11.0（10〜12、2回） |


実時間の成績には、動作の選び方に加え、判定を待つ間に何も操作しない影響も含まれます。
同期の条件は、その待ち時間をゲームの進行から除いたものです。
両方を分けて読むことで、APIの判定時間も結果に関わることを確認できます。


<a id="doomactions"></a>

実時間で、1秒あたりに動作を選べた回数

| 方式 | 回数 |
| --- | --- |
| 規則 | 8.7回 |
| Jev | 3.6回 |


Jevのレスポンス待ちは約0.16秒でした。
レスポンスを待つ間も前の判定どおりに操作する方法は、試していません。

### 費用を換算した条件

Jevの費用は、短い実時間の試行での呼び出し回数から換算しました。
1時間あたり約$0.27という値は、その回数で操作し続ける場合の概算です。
実際に1時間連続でゲームを動かして測った金額ではありません。

[^doom_haiku_time]: Haikuの実時間の判定は1回約5秒で、1ゲームで2〜3回しか操作できませんでした。同期では、1ゲーム分の189判定に15〜18分かかっています。

このゲームの判断は、敵の横位置と見かけの大きさを使って、通常のコードでも書けました。
画像を解釈する処理や、別のゲームでも同じ結果になるかは、この測定に含みません。
