# 評価指標と共通の測定条件


実験の表を読むために、正解の数え方と、費用・待ち時間に含めた処理を説明します。
何を1件の正解としたかは、実験によって異なります。
各実験のデータと結果は、[詳しい測定結果](detailed-results.md)にまとめています。
本文の掲載値は[再集計の手順](reproduction.md#本文の掲載値を保存結果から再計算する)で再計算できます。
分類・呼び分けは英語・日本語とも400件、感情ラベルは300件へ全方式を揃えています。回答拒否は除かず、不正解として数えます。


<a id="metrics"></a>

## 評価指標の読み方

### 分類先など、答えを1つ選ぶ場合

正解率は、判定した件数のうち、正解だった件数の割合です。
問い合わせの分類なら、選んだ分類先が正解と一致したかを数えます。

### 見逃しと誤検出を分ける場合

有害な文章を調べる処理では、有害な文章を見逃す誤りが起こります。
一方、有害でない文章まで止める誤りもあります。
この2つを分けて見るため、適合率と再現率を使います。

- 適合率：有害と判定した文のうち、本当に有害だった文の割合
- 再現率：有害な文のうち、検出できた文の割合
- F1：適合率と再現率の両方を使って、検出の成績を1つの値にまとめた指標

F1は0〜1の値で、計算には調和平均を使います。
式は「2 × 適合率 × 再現率 ÷（適合率 ＋ 再現率）」です。
本書の集計では、適合率と再現率がともに0なら、F1も0とします。

片方が高くても、もう片方が低ければ、F1は低くなります。
見逃しと誤検出で被害の大きさが違う場合は、F1だけで判断せず、両方の内訳を確認します。

### 複数の感情ラベルを付ける場合

感情の判定では、1件のコメントに複数の正解ラベルが付いています。
すべてのラベルを過不足なく付けた件を数えるのが、完全一致です。
1つでも余計に付けたり、必要なラベルを落としたりすると、その件は不正解になります。

ラベルごとの誤りも調べるため、micro F1を併記しました。
正しく付けたラベル、余計に付けたラベル、落としたラベルを、全件・全ラベルで合計します。
その合計から適合率と再現率を求め、F1を計算します。
定義はscikit-learnの解説（<https://scikit-learn.org/stable/modules/generated/sklearn.metrics.f1_score.html>）に沿っています。

完全一致はコメント1件の感情の組を採点し、micro F1はラベルごとの過不足を採点します。
何を減らしたいかに応じて、見る指標が変わります。

### 画像の枠を比べる場合

物の位置を囲む枠は、座標が少しずれただけで不正解とはしません。
予測した枠と正解の枠がどれだけ重なるかを、IoUという値で測ります。
計算は、重なる面積を、両方の枠を合わせた領域の面積で割ったものです。
同じ枠なら1、重ならなければ0になります。
実験10では、IoUの中央値と、0.5以上だった枚数を示します。

## 費用と待ち時間の比較条件

### 費用表で使う単価

費用表の金額は、記録したトークン数に、実験時の公式単価を掛けた概算です。
請求明細やクレジット残高で確認した金額ではありません。
JevはAPIが返した入力トークン数を使っています。


<a id="llmprice"></a>

費用換算に使った単価（100万トークンあたり）

| モデル | 入力 | 出力 |
| --- | --- | --- |
| Jev 1.13 / 1.14 | $0.042 | 無料 |
| Decisions API（gpt-6-luna） | $0.10（キャッシュ読み$0.01、書き込み$0.125） | 無料 |
| Claude Haiku 5.5 | $0.10（キャッシュ読み$0.01） | $0.50 |
| Claude Sonnet 5.5 | $2（キャッシュ読み$0.10） | $10 |


Claudeの単価は、2026年10月13日にAnthropicの料金ページで確認しました。
`claude -p`は入力の一部を1時間有効なキャッシュへ書き込んでおり、この書き込みは入力の2倍の単価（Haiku $0.20、Sonnet $4）です。
表の単価とこの書き込みの単価で`claude -p`のトークン数から計算すると、記録された費用と一致しました。

### Claude Codeに共通する入力の扱い

JevはAPIを直接呼び、ClaudeはClaude Codeの`claude -p`から呼びました。
Claudeにも、判定する文章と質問を渡し、JSONスキーマでレスポンスの形式を指定しています。
空のディレクトリで実行し、`--setting-sources project,local --strict-mcp-config`で測定する人の個人設定（`~/.claude/CLAUDE.md`、MCPサーバーなど）を読み込ませていません。
この指定は`scripts/lib/claude-cli.ts`の`ISOLATION_ARGS`にあります。

測定時のClaude Codeは、判定する文章のほかに、システムプロンプトなどを毎回1,052〜1,073トークン送っていました。
この部分を、本書では共通入力と呼びます。
個人設定を読み込んでいた10月の測定では、共通入力が約2.6万トークンありました。

共通入力をすべて数えると、APIを直接呼ぶ場合よりClaudeの費用を高く見積もります。
文章の実験では、最小の入力で呼んだときのトークン数を共通入力として差し引きました。
残った量に、表の単価を掛けています。
構造化出力のツール定義は、回答を指定したJSON形式にそろえるための入力です。
直接APIでも同じ定義を渡す条件で、406トークンを加えました[^tool]。

[^tool]: Anthropicの料金ページに載っている、ツール利用時に追加されるシステムプロンプトのトークン数です。

### キャッシュと回答前の推論

毎回同じ選択肢の一覧などは、プロンプトキャッシュで再利用できます。
再利用する部分の入力単価が下がるため、キャッシュを使う条件の費用も並べました。

一方、拡張思考は、Claudeが回答前の推論に追加のトークンを使う機能です。
そのトークンにも料金がかかり、回答までの時間も増えます。
今回のHaikuは、多くの呼び出しで拡張思考を使っていました。問い合わせ分類では、英語100件のうち74件です。
Sonnetは、ほとんどの呼び出しで拡張思考を使いませんでした。

費用表の「拡張思考込み」は、記録した推論トークンを含む金額です。
「拡張思考なし」は、その分の費用を差し引いた計算値です。
Haikuを拡張思考なしで呼び直したわけではありません。
そのため、「拡張思考なし」の費用と、測定した正解率を組み合わせて性能を判断することはできません。

### 待ち時間に含む処理

文章の実験では、Claude CodeがAPI呼び出しの時間として返す`duration_api_ms`を使いました。
Claude Code自体の起動時間は含みませんが、共通入力を読む時間は含みます。
ネットワークの待ち時間とモデルの処理時間は分離していません。
ロボットアームのGeminiは、書籍の「写真の判定とロボットアーム」の該当節に示す別の方法で測りました。

最小入力でもどれくらい待つかを見るため、"ok"と送り、真偽を1つ返させる呼び出しも測りました。
条件ごとに10回ずつ呼んだ結果は、次のとおりです。


<a id="minimumlatency"></a>

最小入力でClaudeを呼んだときの待ち時間

| モデルと条件 | 記録された待ち時間 |
| --- | --- |
| Sonnet（応答モデル版未保存） | 6回は1.3〜1.5秒、残り4回は4.8〜9.2秒 |
| Haiku（応答モデル版未保存）、拡張思考込み | 1.6〜2.3秒 |


この値にも、共通入力を読む時間などが含まれます。
ClaudeのAPIを直接呼んだ場合は測っておらず、モデル単体の速度とは区別します。

## 差が偶然かを確かめる

正解率に違いがあっても、評価用のデータを変えると大小が逆になる可能性があります。
本書では同じデータを両方式に判定させ、どちらか一方だけが正解した件数を比べました。

Jevだけが正解した件数と、比較相手だけが正解した件数に偏りがあるかを調べます。
この方法をMcNemar検定といい、計算には正確検定を使いました。

p値は「本当は正解率に差がない」と仮定した場合に計算する確率です。
今回と同じか、それ以上に極端な偏りが出る確率を表します。
「差がない確率」や「このモデルが正しい確率」ではありません。
定義はNISTの解説（<https://www.itl.nist.gov/div898/handbook/prc/section1/prc131.htm>）を参照してください。

詳しい測定結果の「差は偶然と区別できない」は、p値が0.05より大きかったという意味です。
同じ性能だと証明したわけではなく、このデータでは差を確認できなかったということです。
また、各件の正解・不正解を比べる検定なので、F1の差を直接調べたものではありません。

比較する方式を増やすとたまたま差が出る機会も増えますが、多重比較の補正はしていません。

## 評価した範囲

- 文章の実験で、criteriaに説明や例を足す方法はほとんど試していません。画像の実験9では、説明文に見本画像を足す条件を比べました
- 画像の実験は6品種の計60枚です。未知の品種を拒否する判定、複数の対象、動画は測っていません。有無の判定も、犬猫のいない画像と、自転車のある画像では試していません
- ロボットアームで掴む試験は、同じ物をほぼ同じ場所で掴んだ5回です。別の物を対象にした場合、指定と違う物を掴んだ場合、爪が隠れた場合の判定は試していません。探索・追跡を含む作業全体の費用も集計していません
- 問い合わせの分類では英語と日本語を測りましたが、別の分野でも同じ結果になるかは分かりません
