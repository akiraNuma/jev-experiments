# Decisions APIとの比較

書籍の実験1〜9・11では、JevとOpenAIのDecisions APIを比べています。
Decisions APIのモデルはgpt-6-lunaです。
同じ文章・写真・判定内容を、各APIのリクエスト形式で渡しました。
Jevの掲載コードと同じ用途を、別の判定用APIで実装したときの比較です。

## 条件のそろえ方

- 質問文・選択肢・条件は、Jevに渡した文言をそのまま使います。Decisions APIにだけ文を足したり、言い換えたりしません。
- Decisions APIのpredicateには、Noulの条件（true/false）の項目がありません。そこで`noulAsPredicate`（`scripts/lib/decisions-api.ts`）で、質問文の後ろに`True:`・`False:`の見出しを付けて並べます。
- Jevで行った段階（しきい値の調整、渡し方の比較、初版の質問の評価と、その誤りを見た1回の修正）は、Decisions APIにも同じデータ・同じ手順で行います。質問の修正では、Decisions API自身の誤りだけを見ます。
- しきい値は0.01〜0.99を0.01刻みで試し、範囲の端で止まらないようにします。
- 段落の並べ替えでは、確率が同じ段落はどの順にも等しい確率で並ぶとして数えます。Decisions APIは確率を小数2桁で返すため、元の順で並べると段落の位置の影響を受けます。
- 通信の失敗（HTTP 5xx・タイムアウト）は判定ではないので、その件だけ測り直します。
- 回答拒否は、どのAPI・モデルでも不正解として数え、集計から除きません。1件1ラベルの分類では不正解で、確信度がないので確信度で振り分ける集計では確認待ち（呼び分けではHaikuへ回す側）に入れます。複数ラベルでは、拒否した感情を付けなかったものとして数えます。回答が保存されていない行は、ラベルを1つも付けなかったとみなします（`experiments/findings.md`のF-047）。

2026-11-05に、上の形にそろっていなかった実験3・4・5・9と実験2の調整を測り直しました。旧結果は各データの`archive-*-20261105/`にあります。経緯は`experiments/findings.md`のF-047です。

## 保存結果を再集計する

再集計のコマンドは、READMEの[保存済みの結果を読む・再集計する](../README.md#保存済みの結果を読む再集計する)にまとめています。

`report-decisions-book.py`は、問い合わせ分類、感情ラベル、有害判定、問い合わせの呼び分けをJSONで出力します。
評価ID、正解数、費用、待ち時間と、使用した保存結果のSHA-256も出力します。
問い合わせ分類と呼び分けは英語・日本語とも400件、感情ラベルは300件です。
各方式を同じ評価IDへ揃えています。

感情ラベルは、しきい値以上のものがなければ最も高い感情を1つ返します。
Jevは0.5と、調整用データで選んだしきい値を表示します。
Decisions APIも、0.5と、同じ調整用データ・同じ手順で選んだしきい値を表示します。

有害判定は、分類結果のまま使う条件と、調整したしきい値以上で保留する条件を表示します。
しきい値は、JevとDecisions APIのそれぞれで、データの前半1,923件から同じ手順で選んだ値です（Jev 0.06、Decisions API 0.03）。
比較は、保存した300件のうち、しきい値の調整に使っていない後半の150件だけで行います（全方式とも同じ150件）。
呼び分けの費用は、Haikuが分類先の一覧をキャッシュする条件の試算です。
Claude Codeで記録した費用を、そのまま直接APIの利用料とは扱っていません。

## ほかの実験の保存結果

段落選びは、書籍に掲載したbatch-localの保存結果を使います。
元データの取得とライセンスは`experiments/DATA.md`を参照してください。

ゲームは各条件10回の平均で、同じ敵の出現を揃えた対比較ではありません。

費用は、各APIが返した利用量と測定時の公式単価による概算です。
Decisions APIのキャッシュ読み取り・書き込みも記録に応じて換算しています。
測定日と同時実行数はAPI間で揃えておらず、待ち時間は各実行時の値です。
